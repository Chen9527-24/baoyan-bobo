# 宝妍设备控制内核（本地主机原型）

状态：**C++17 主机验证，未上板**。这里实现设备端控制规则；没有麦克风驱动、声学 AEC、唤醒词模型、ESP-SR、BSP、网络鉴权或本地大模型。没有连接宝妍线上服务，不改变当前 H5／服务端，不包含真实凭据、家庭资料或假定硬件引脚。

这层的作用是把“什么时候可以开始收音、播放、打断及释放资源”固化下来，后续更换板子或语音供应商时复用。它不证明实体设备的唤醒、回声处理、打断速度、声音自然度或方言质量已通过。

## 已实现的控制行为

- 唤醒／开始先请求会话。收到适配器确认的已鉴权会话后才请求对话采集；采集器确实启动回执后才进入 `listening`。界面不得把请求发出当成已经收音。
- 本地停止／结束释放采集、清空播放、取消旧回复并关闭会话；这些动作不等待云端取消确认。
- 音量在 0–100 间限制，直接发给设备适配器。百分比不是声压安全认证；最终板子的音量曲线和上限另行确定。
- 断网或连接替换释放资源；重连仅回到待机，**不会恢复前一段对话或自动打开对话采集**。需要新的唤醒或明确开始。
- 物理静音优先。静音立即废弃会话并要求切断采集／播放；解除静音不会自动开聊。迟到的采集启动回执会收到针对旧句柄的释放动作。
- 只有“实际板级双工已验证”配置与 `AecQualifiedNearEnd` 人声证据同时满足，才允许播音中自动插话。首个动作先停本地播放，第二个动作再取消对应的上游旧回复，随后打开新回复代次。
- 不通过音量、RMS 或单纯 VAD 能量判断说话人；`UnverifiedActivity` 和播音时的普通 `NearEndSpeech` 不触发自动打断。
- 接收音频必须同时匹配当前连接／会话／回复代次，并已收到同代次的回复开始标记；拒收旧音频、无代次音频、重复及乱序帧。
- 服务端生成结束不代表耳朵听完。只有播放队列实际排空回执才回到下一轮；插话会清理尚未播放的旧队列。
- 排队中的旧唤醒事件携带观察时的 `control_epoch`。停止、静音切换及重连使旧事件失效，避免迟到唤醒重新开麦。
- 声学起句和结束使用同一个、在采集句柄内严格递增的 `utterance_id`；双工复用采集器也不复用声学句身份。迟到旧结束不能提交新插话，重复旧起句不能再次打断。
- 采集帧入队时冻结回复代次，上传前再次核验；切轮前排队的旧音频不能在临发送时被重新贴成新轮数据。

## 安全默认值和语音模式

`Config::board_duplex_validated` 默认为 `false`：完成用户一句话后释放对话采集，再播放回复；本地队列排空后重新开始对话采集。这是尚无真实声学验证时的保守行为，不代表最终用户体验选成逐句按钮操作。

只有真实样机的麦克风、喇叭、AEC 参考通路与近端人声判定通过验证后，才能开启双工模式：对话采集在等待／播音中持续运行，合格的人声事件自动打断，用户不需要逐句点击。配置为 `true` 本身不会产生 AEC 能力。

`capture_active` 表示本次对话的采集链路，不等于整块硬件的供电状态。待机唤醒检测器若需要常开麦克风，应在 BSP／ESP-SR 适配器中明确处理本地音频且不上传；物理静音必须同时切断待机唤醒和对话采集。

## 在本机运行

在本目录执行：

```sh
sh scripts/run-native.sh
```

默认使用 `clang++`，可以通过 `CXX` 指向另一个支持 C++17 的编译器。结果在 `build/native/`，其中 `simulation.jsonl` 全部标记 `simulation_only: true`。本地生成目录不进入产品发布包。

已安装 CMake 的环境也可执行：

```sh
cmake -S . -B build/cmake -DBUILD_TESTING=ON
cmake --build build/cmake
ctest --test-dir build/cmake --output-on-failure
```

当前主机没有在 PATH 找到 CMake，因此本轮实际运行的是 native 脚本；不声称 CMake／ESP-IDF 构建已验证。没有自动下载安装 SDK、模型、驱动或编译工具链。

## 接下来需要适配的部分

1. 按最终板子实现 BSP：音频输入输出、物理静音、按钮、指示灯和音量；不预先猜测引脚。
2. 接入 ESP-SR／等价声学前端：本地唤醒、近端人声、AEC 参考信号与状态；先验证喇叭回声、电视、人声插话、远近距离。纯能量触发不能填充“已验证人声”事件。
3. 做受限播放队列和清空机制：包含解码器、软件队列、DMA／驱动残留音频；旧代次回调不能在清空后再次发声。
4. 适配已鉴权的设备网关：绑定账号／家庭，短期会话权限，连接与回复代次映射，错误／超时关闭。普通设备标识和计数器不作为登录凭据；不把供应商长期密钥放进设备。
5. 真实上板验证内存、实时调度、延迟、音量、续航和网络失效，再决定是否启用双工。当前没有实物，未完成以上验证。

该模块没有聊天记忆、儿童内容策略、家长授权或场景调优数据库；这些继续由已授权服务管理。本地动作与 JSON 示例均为待协商草案，不能直接发送到现有线上接口。
