# 设备适配契约草案

版本：本地原型 0.2，2026-10-15（加入声学句身份及采集帧归属检查）。**尚未与设备 BSP、ESP-SR 或现有服务端联调，不是生产协议。**

## 执行规则

`Controller` 是单任务状态机，不提供内部锁。硬件、声学和网络事件必须送入同一顺序执行队列；应用动作批次时不得跨批重排。物理静音中断必须先由电气／驱动侧关闭真实采集，再通知控制内核，不能等待普通网络队列清空后才生效。

同一批次中的 `StopPlayback` 必须先同步清除本地解码／播放／DMA 队列，再异步处理 `CancelResponse`。后者只适用于动作携带的旧连接与旧回复，断网时允许尽力取消或放弃，**不得积压后发给新会话**。取消网络失败不允许恢复已停止的本地音频。

适配器操作都要可重复释放，并按动作上的标识操作对应句柄。`captureStarted` 的迟到回执可能生成一个只针对旧 `CaptureToken` 的 `StopCapture`；不能把它理解为关闭当前新采集器。

迟到的 `playbackStarted` 也会产生只针对旧回复代次的 `StopPlayback`，不能误停新回复。真正开始驱动喇叭前仍须校验当前有效代次；事后回执清理只是兜底，不能接受先播旧音频再通知内核。若当前回复尚未被批准入队却报告开始发声，内核按适配器故障结束会话。

`sessionOpened` 仅在网关已完成设备身份、账号／家庭权限、使用限制校验之后通知内核；连接 TCP／WebSocket 成功不等于已授权会话。鉴权失败、录音失败、播放队列溢出或等待超时应调用当前代次的 `adapterFailed`，结束会话并释放资源。超时计时器由适配器实现，当前内核不持有时钟。

## 标识和陈旧事件

- `connection`：适配器提供，在一次控制器生命周期内严格递增；重连必须换值。迟到断网事件不能影响新连接。
- `session`：本地内核每次新的唤醒／开始递增。
- `turn`：同会话的回复代次，正常播完或插话后递增；取消旧回复不会关闭持续会话。
- `capture`：每次打开对话采集递增。双工插话保留采集标识，不重开麦克风。
- `utterance_id`：适配器在声学起句被观察时分配的非零、严格递增 ID；同一个 `CaptureToken` 内不复用，起句与结束回调携带同一个 ID。声学起句迟到／重复时不能重新编号伪装成新事件。ID 计数用完时结束采集重新建句柄，不允许回绕。新采集句柄可从 1 开始。
- `control_epoch`：观察到唤醒／开始时保存，不要等事件出队时才读取最新值。停止、静音切换、重连使排队的旧开始意图失效。

这些编号不是秘密，也不能用于鉴权。设备重启要销毁所有旧 socket／播放／采集资源；网关还需使用不混淆的启动或连接身份，不能仅凭会从 1 重新开始的本地计数器接受旧流量。

采集帧在**采集／进入发送队列时**调用 `captureTarget(captureToken)`，把返回的 `TurnToken` 与该帧一起冻结保存；结果 `session == 0` 时不能入发送队列。实际发送前用 `mayUpload(captureToken, frozenTurnToken)` 再次核验；若切轮、结束、静音或断网使其失效，就丢弃旧队列帧，不能在发送前重新取得当前 turn 来改贴标签。这些检查不能替代物理静音硬件门控。

同一近端人声帧应先完成声学事件处理、得到新轮次，再冻结该帧的归属。语音前滚缓存的归属与声学起句时间需在真实适配器中明确对齐；本内核不保存 PCM，不提供跨旧轮缓存重标机制。

播放帧先解析／校验大小、编码、鉴权与代次，交给 `audioFrame(turnToken, sequence)`；只有返回 `QueueAudioFrame` 才可入队。PCM 载荷不存于内核，适配器必须自行设队列上限。序号需从 0 开始且严格连续；异常缺帧不得悄悄跳序复播，应由适配器结束当前流或执行明确恢复流程。

## 声学事件要求

`UnverifiedActivity`：噪声、能量变化或还不能排除回声的活动；没有自动提交、自动打断资格。

`NearEndSpeech`：适配器识别到用户人声，可在正常收听时标记本轮开始；不能据此在宝妍播音期间打断。

`AecQualifiedNearEnd`：必须来自**已验证的具体板级音频链路**，AEC 参考信号有效，近端人声判定满足既定条件；同时 `board_duplex_validated` 为真时才可播音插话。该枚举是接收已验证证据的契约，内核没有计算、校验或保证声学真假。

不允许把 RMS 阈值、收到任意 PCM、模型回复声音或仅本地提示音转换成 `AecQualifiedNearEnd`。演示与测试手动注入这个事件，仅证明控制分支行为。

`speechStarted(captureToken, utteranceId, evidence)` 只接受比该采集器已接受起句 ID 更大的起句；重复／旧起句不会被当作插话。`utteranceEnded(captureToken, utteranceId)` 只接受当前有效起句的相同 ID，一次提交后重复结束无效。两者都必须携带采集时确定的身份，不能在回调送达时读取当前 ID 来补写。

`utteranceEnded` 是声学前端确认的一轮自然停顿，且必须先有有效人声；不是按钮要求。`UtteranceFinished` 动作包含同一 `utterance_id`，是抽象动作，不保证对应供应商 `commit`；原生自动 VAD 接口可能不需要额外网络动作，需适配层确认，避免重复提交。

## 输出完成

`replyEnded` 表示供应商生成结束。`playbackDrained` 必须同时确认该回复输入已结束，并且解码、软件队列、驱动／DMA 都实际播放排空；不能只用网络 EOF 或预计音频时长代替。

`playbackStarted` 由真实输出启动回执驱动。提前收到音频时显示 `reply_queued`；真正开始发声才显示 `speaking`。双工时 `capture_active` 可与 `speaking` 同时为真，应明确提示仍在收音。

```json
  "draft": true,

}
```

真实 wire schema、帧格式、采样率、压缩编码、鉴权、设备绑定、限流、重试、错误码和服务端代次映射全部待联调确定。此模块不监听端口，不提供 HTTP 服务，也不读取配置密钥。
